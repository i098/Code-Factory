Crewship

Turn a fresh Ubuntu machine into a reproducible AI-agent coding host: Herdr, Firstmate, the omp agent fleet, and the Concord and slk chat clients, provisioned by Ansible from a checksum-verified toolchain.

Ship's manifest

  • Quick start

    The gangway. Clone the repository on Ubuntu 24.04 or 26.04, run ./onboard.sh, then ./ship.sh dock, inspect, chart and launch.

  • The ship.sh commands

    The helm. dock writes .local/host.yml, inspect checks it, chart runs the playbook in check mode, launch is the only step that changes the host, and survey checks the result.

  • The omp agent fleet

    The mast. omp is the agent harness Crewship installs: sign-in, model roles, fallbacks and the advisor.

  • Herdr sidebar

    The crow's nest. The Spaces and Agents sidebar layouts show every workspace and agent, fed by a reporter timer and an omp extension.

  • Firstmate

    The sail. The firstmate profile installs the Firstmate orchestrator and seeds its crew dispatch and omp overlays from this repository.

  • Dependencies

    The cargo hold. Every tool tracks its latest release and is verified against the checksum its publisher posts.

  • Security

    The cabin. What is never exported, how to handle credentials, and remote access.

  • Fleet guards

    The bow lantern. Shared Supabase, Docker guard, dev-server reaper, storage guard, spawn memory floor and the browser ladder keep a fleet host out of swap exhaustion.

  • CI pool

    The containers on the quay. Self-hosted GitHub Actions slots: one job per fresh container, sized from half of the host's CPU and memory.

  • Chat clients

    The radio mast. The Concord (Discord) and slk (Slack) terminal clients, each in its own Herdr tab.

  • Crewship on GitHub

    The sign on the dock. The source, the docs and the issues.

  • Releases

    The harbor office. Tagged releases, with the notes from the changelog.

  • Architecture

    The lighthouse. Why Ansible, the host and container boundary, the Docker worker, and CI.
