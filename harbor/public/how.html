How this harbor is built

  • Renderer. Each rendered frame casts one ray per character cell from your eye, except cells still covered by intro noise. Buildings, the dock and the hull are convex solids made of planes. Masts, barrels, tree trunks and the lighthouse are true cones with smooth normals. Rocks and tree canopies are ellipsoids. The sea is a height field of travelling waves, ray marched per cell; the ship and the boats ride it.
  • Light. Exterior lamps, lit windows, the lantern and the beacon light nearby surfaces, with brightness that decreases with distance. Exterior solids cast shadows when shadow rays are enabled. The lighthouse beam sweeps; the moon gives a dim fill. The room lamp lights nearby surfaces without shadow rays. The sea shows Fresnel reflection, moon and lamp highlights and foam. Fog and contact shadows add depth.
  • Characters. Brightness usually picks a glyph from the density ramp .`',:;~-=+*#%@▒▓█ and one of eight colour levels per material. Grass uses blade glyphs; pale paving marks and foam keep their texture glyphs with a minimum brightness that decreases in fog. Fountain water uses animated texture glyphs instead of the density ramp. An edge glyph (| - / \ _) is drawn wherever one surface meets a farther one.
  • Frame loop. requestAnimationFrame moves you, the sea and the ship and redraws the grid on a canvas. A ray tests solids whose screen box reaches its tile of cells, nearest first. It stops when no remaining solid can be nearer than its hit. After the intro, the canvas keeps unchanged rows. Devices without (pointer: coarse) draw rows with changed cells again from their full text-run positions. Touch devices redraw only the changed span and its neighbouring cells. The mini map draws again each frame, even when its cells do not change. Devices with (pointer: coarse) draw one glyph per fillText call to limit WebKit's text cache. Their canvas uses at most 2 device pixels per CSS pixel. Other devices draw one run of one colour per call. The backing-store area stays at or below 4096 * 4096 device pixels; this does not limit each dimension to 4096. Large high-DPR windows use a lower rendering ratio, which can fall below 1. Grid measurement clears the complete canvas, including padding, even when the backing-store size does not change. The intro overlay uses CSS dimensions to cover the transformed canvas at any rendering ratio. The first grid measurement waits for fonts; if the requested font fails to load, the scene uses a fallback font. For a fixed exterior viewport, the glyph size stays fixed; slow frames can disable shadows without changing the view. Resizes wait until the viewport settles, then update the canvas immediately before the next draw. Slow rendering first disables exterior shadow rays, if enabled, then uses larger room glyphs with fewer cells. Fast room rendering restores a finer grid. Inside the room, missed frames also reduce detail relative to the measured display refresh rate. Before counting slower callbacks as painting load, the renderer skips one repaint to measure the display period without that load. This sample also detects display refresh changes during continuous input. Each door crossing requests the same unloaded sample, so timing from the previous scene does not hide room painting load. The room redraws only after movement, looking, resizing, or another change that requires a new frame. Reduced motion also stops exterior animation.
  • Intro rendering. The sweep shifts a single cached 8x8 glyph tile over cells that still hide the scene. It uses the same canvas without a cached scene. Each intro frame ends with a black canvas fill at opacity 1 - progress * progress. Desktop drawing keeps the colour runs; touch drawing sends each glyph directly to the existing single-glyph painter. The mini map, feature labels, and touch pad stay hidden until the intro ends.
  • Controls. WASD or arrows walk and turn, R and F look up and down, the mouse looks around, Enter opens what you point at. On a phone, the bottom-left pad walks; drag on the right to look around. The pad, labels, intro card, and map controls respect safe-area insets. In landscape, the intro card leaves the map visible. Feature labels float beside their objects, with a leader line in text, and hide when their objects are behind you. On a phone, feature labels stay above the pad; scroll tall labels to reach their links.
  • Mini map. Outside, M picks a point on the text map in the corner. Press M again to fill the screen with the map. Use the arrows to choose a point, then press Enter to walk there. On a phone, tap a point. With reduced motion, map selections move you to the point immediately. See the house guidance for door crossings and controls inside.
  • Content. harbor/build.py builds the points of interest with the README's Features list and More docs row, and the changelog.
  • Deploy. harbor/ is plain HTML, CSS and JavaScript with no dependencies. A GitHub Actions workflow builds it and deploys it to Cloudflare Workers static assets on every push to main and on each release; nothing in harbor/ ever reaches a Crewship host or image.
