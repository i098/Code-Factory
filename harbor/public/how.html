How this harbor is built

  • Renderer. Every frame casts one ray per character cell from your eye. The world is a list of convex solids, each a set of planes, plus the water plane; the ship's solids live in their own frame that bobs and rolls at the dock. The nearest hit picks the cell.
  • Characters. Light and how squarely a face turns to you pick a glyph from the ramp .:-=+#. Floors stay sparse, water ripples in ~ - ., and an edge glyph (| - / \ _) is drawn wherever one surface meets a farther one, so shapes read as outlines.
  • Frame loop. requestAnimationFrame moves you, rocks the ship and redraws the grid on a canvas, one fill per run of one colour. The grid is sized to the screen; on a slow phone the glyphs grow so there are fewer cells. With reduced motion the scene stands still and redraws only when you move.
  • Controls. WASD or arrows walk and turn, R and F look up and down, the mouse looks around, Enter opens what you point at. On a phone the pad walks and a drag looks. The label floats beside what you point at, with a leader line in text.
  • Mini map. M picks a point on the text map in the corner, M again fills the screen with it; arrows choose, Enter jumps there. On a phone, tap a point.
  • Content. harbor/build.py builds the points of interest from the README's Docs table and the changelog, so the page follows Crewship as it changes.
  • Deploy. harbor/ is plain HTML, CSS and JavaScript with no dependencies. A GitHub Actions workflow builds it and deploys it to Cloudflare Workers static assets on every push to main and on each release; nothing in harbor/ ever reaches a Crewship host or image.
